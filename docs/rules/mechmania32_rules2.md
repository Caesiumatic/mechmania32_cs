## 2. 官方炮击语义与生产查询

### B2/B3 权威查询边界

- **CODE**：`trace_shot` 接受射击时刻的炮口位置、单位方向、地图、敌方圆、载具与双方矿点圆；友军不进入场景，因此与官方实现一样可穿透。
- **CODE**：射线按固定引擎的严格先后和严格小于更新首碰；受保护敌人仍可终止射线，但只出现在 `physical_mask`，不出现在 `damageable_mask`。
- **CODE**：没有更早首碰时在射程端点爆炸；爆区使用 `bot.radius + base_blaster_splash_radius` 的中心距离；墙使用与固定引擎一致的格网遍历。
- **TESTED**：256 个固定生成 seed 与官方 `geom::scan` 及 `eval_tick` 对照。纯 scan 最大爆点误差为 `0.0`；完整单 tick 最大误差为 `0.000027771415`，低于采用的引擎 `EPSILON=0.001`；首碰类型、物理覆盖 mask、可承伤 mask 差异均为 0。
- **OPEN**：这一结论只证明已知 firing-time 坐标的几何查询。比赛遥测还包含敌方匀速预测和实体碰撞修正误差，不能把其全部归因于射线模块。

### D03 受保护近敌仍决定首碰

## 3. 单步动作时序与保守范围

- **CODE**：全队先生成移动意图，普通开阔移动按 `actual_move_delta` 规范化；再计算转向限速、载具三态位置和保守实体接触；之后统一分配射击与治疗，避免 BotId 遍历时看到不同队伍快照。
- **TESTED**：短移动向量不被错误放大；转向限制、载具位置三态、实体合法支援点均有单元或几何场景覆盖。
- **OPEN**：敌方下一位置采用 `pos + vel` 的行为模型，未完整投影敌方与墙、载具、矿点碰撞。复杂接触可造成比赛级预测误差；报告将其与纯 ballistics oracle 分开。
- **OPEN**：自身 firing-origin 因动态碰撞不确定而提前拒绝时，当前没有增加 `geometry_uncertain_candidates`，因此该遥测计数可能低报；行为是保守不射，不是错误把不确定候选当精确命中。

## 4. 治疗支援与有效容量

### C1 支援锚点

- **CODE**：治疗目标和移动支援锚点分离。满血时治疗者在 Battle、载具控制者或其他活跃友军中选择稳定锚点，并使用切换惩罚保持任务连续。

### C2 本 tick 可兑现治疗优先

- **CODE**：第一阶段基于全队预测位置预留当前可兑现治疗，并让恰好位于范围边缘的治疗者原地保持；只有无当前通道者才赶往支援位。第二阶段在统一移动快照上分配治疗，按缺血容量与 `heal_stack_cap` 截断。
- **CODE**：目标必须存活、不是治疗者自身、在中心距范围内、可由最大转向后的朝向覆盖，且静态 LOS 可见。
- **TESTED D07**：附近可兑现目标优先于更远但更低血目标；精确范围边缘通道在支援赶路前被保留。
- **TESTED D08**：友军移动后进入/离开范围、治疗者转向限制、三通道上限、满血目标与无效目标均有断言。
- **TESTED D09**：`d09_death_slot_reuse_and_tick_jump_drop_stale_coordination_cache` 覆盖死亡、首空槽复用、目标失效和跳 tick 后缓存清理。
- **TESTED D10**：支援点靠近载具或矿点时会搜索合法环形位置，动作有限且保持朝向/移动连续。

### R05 范围与朝向精确子合同

- **CODE**：中心距 `<= base_heal_range`，方向差 `<= base_heal_arc_deg / 2`；等号包含在内。不能自疗，且静态墙 LOS 必须通过。
- **DOC**：默认治疗范围 3，完整弧 90°，即半角 45°。
- **TESTED**：基础自身/范围/朝向合同通过；`r05_range_boundary_includes_exactly_three_and_rejects_just_outside` 断言 3.0 包含、刚超过排除；`r05_arc_boundary_includes_exactly_45_degrees_and_rejects_just_outside` 断言 45° 包含、刚超过排除。
- **OPEN**：当前可兑现治疗只精确使用静态墙 LOS；动态实体不阻挡官方治疗 scan，因此无需加入动态遮挡。
